# Контекст для ИИ-агентов

Эта папка — единая точка входа в проектную документацию для ИИ-агентов
(и людей). Точка входа в репозиторий — `AGENTS.md` в корне; он ссылается сюда.
Новые агентные документы складывайте в эту папку и добавляйте строку
в таблицу ниже.

## Что читать под какую задачу

| Задача | Читать |
| --- | --- |
| Любой UI, цвета, компоненты, тёмная тема | `material_design_3_dark_theme_guide.md` → `m3-motion.md` |
| Анимации, переходы, фон | `m3-motion.md` (+ реализация в `app/m3-motion.css`) |
| API, генерация роудмапов, серверный LLM-шлюз | `backend-integration-contracts.md` → `backend-integration-status.md` |
| Безопасность бэкенда, секреты, лимиты | `backend-security.md` |
| Генерация дня, сессии, XP-правила | `day-session-generation.md` |
| Как проверялся mock-сценарий дня end-to-end | `mock-e2e-day-session.md` |

## Файлы

- **`material_design_3_dark_theme_guide.md`** — строгая спецификация M3 Dark
  (Graphite & Purple): поверхности, текст, лавандовый акцент `#D0BCFF`,
  радиусы, запреты (чистый чёрный, неон, холодный синий). Источник истины по
  визуалу; hex вне спецификации запрещены.
- **`m3-motion.md`** — motion-система: токены кривых/длительностей M3,
  паттерны (ripple, каскады, переходы экранов), решение по ambient-фону
  и бэклог идей ближе к MD3.
- **`backend-integration-contracts.md`** — контракты Route Handlers:
  валидация, нормализация ID, инварианты графа и XP, аудитный бейзлайн.
- **`backend-integration-status.md`** — что из бэкенд-интеграции уже
  реализовано (эндпоинты генерации, проверки), а что нет.
- **`backend-security.md`** — граница безопасности: `LLM_API_KEY` только на
  сервере, лимит тела 128 KiB, что никогда не попадает в ответы и логи.
  Требование API-ключа для работы — осознанное решение владельца, не баг.
- **`day-session-generation.md`** — контракт генерации дня (Stage 2):
  66 дней — учебные сессии, а не календарь; правила эффективного дня и XP.
- **`mock-e2e-day-session.md`** — отчёт о прогоне mock-сценария дня
  (`NEXT_PUBLIC_BACKEND_MODE=mock`, без реального LLM-ключа).

## Правила ведения

1. Один документ — одна тема; имя файла на английском, `kebab-case`.
2. Устарело — исправь или удали в том же коммите, что и код. Статус-документы
   (`backend-integration-status.md`) обновляются при каждой интеграции.
3. Не дублируй правила между документами — ссылайся на источник истины
   (например, цвета живут только в гайде темы и в CSS-токенах).
